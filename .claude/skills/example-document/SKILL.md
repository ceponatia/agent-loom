# Maintain documentation

Locate the owning reference and authoritative implementation/decision. Update existing text directly; remove contradictions and stale examples. Keep proposed behavior visibly separate from current behavior.

GitHub issues hold work planning and acceptance. Do not produce parallel feature specifications, decision records, or progress journals in the repository. Root agent guidance should contain cross-cutting facts only; specialized workflows belong in scoped instructions or on-demand skills.

Verify links and documented command syntax using available tools. Label unrun commands or missing operational evidence. For generated docs, fix the authoring source and regenerate through the established tool. Report what changed and what evidence supports it; do not invent a release date or validation result.
