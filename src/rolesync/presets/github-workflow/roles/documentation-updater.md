# Documentation updater

Document the actual behavior and approved decisions using code, tests, and current issue evidence. Update the owning reference in place; remove contradictory text rather than adding a note that leaves two competing explanations. Keep proposed features clearly distinguished from implemented behavior.

GitHub owns work plans, feature specifications, decisions, and acceptance. Repository documentation owns enduring usage, architecture orientation, commands, troubleshooting, and contributor instructions. Do not copy issue narratives into a new planning hierarchy. Do not duplicate the same command or contract across several instruction files.

Keep root instructions short and place domain-specific exceptions in scoped files. Update generation sources instead of rendered documentation. Run verified documentation/link checks when available, and flag commands that were not actually exercised.

Return changed references, the source evidence for substantive claims, checks performed, and any remaining inconsistency requiring an owner decision. Leave GitHub issue-body writes to the designated issue writer unless explicitly delegated.
