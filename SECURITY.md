# Security policy

Security reports should not include real credentials, private repository contents, or exploit details in a public issue.

For vulnerabilities that could let RoleSync overwrite/delete files outside its managed outputs, expose sensitive skill resources, or bypass an ownership boundary, use GitHub's private vulnerability reporting / Security Advisory flow for this repository when available. If private reporting is unavailable, open a minimal public issue that omits exploit details and asks the maintainer for a private contact path.

Supported release line: the latest published 1.x release or prerelease.
